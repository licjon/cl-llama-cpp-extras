* cl-llama-cpp-extras

Optional extensions for [[https://github.com/licjon/cl-llama-cpp][cl-llama-cpp]] that depend on C++ internals not
covered by the public C API. Each extension lives in its own ASDF system
under the =cl-llama-cpp-extras/= prefix. All extensions share a single
unified C++ shim library (=libllama-extras-shim.so=), built automatically
on first load.

** Extensions

*** =cl-llama-cpp-extras/json-schema=

Convert JSON Schema strings to GBNF grammars for constrained generation. Wraps
llama.cpp's =json_schema_to_grammar()= (a C++ function in =libllama-common=) via
a thin C shim with =extern "C"= linkage.

#+begin_src lisp
;; Convert a JSON Schema to a GBNF grammar string
(cl-llama-cpp-extras/json-schema:json-schema-to-grammar
  "{\"type\":\"object\",\"properties\":{\"name\":{\"type\":\"string\"}},\"required\":[\"name\"]}")

;; Use the grammar for constrained generation
(let ((gbnf (cl-llama-cpp-extras/json-schema:json-schema-to-grammar schema)))
  (cl-llama-cpp:generate ctx prompt :grammar gbnf))

;; Or create a sampler directly (for manual chain building)
(let ((gs (cl-llama-cpp-extras/json-schema:make-json-schema-sampler model schema)))
  (cl-llama-cpp:with-sampler-chain (chain)
    (cl-llama-cpp:sampler-chain-add chain gs)
    (cl-llama-cpp:sampler-chain-add chain (cl-llama-cpp:make-dist-sampler 42))
    (cl-llama-cpp:generate ctx prompt :sampler chain)))
#+end_src

Signals =json-schema-parse-error= (malformed JSON) and =json-schema-conversion-error=
(invalid schema), both subtypes of =cl-llama-cpp:llama-error=. A =use-different-schema=
restart is established for interactive recovery.

*** =cl-llama-cpp-extras/json-partial=

Parse incomplete JSON mid-generation by adding missing closers. Wraps
llama.cpp's =common_json_parse()= from =json-partial.h=. Useful for streaming
tool-call extraction — lets you parse partial JSON output before the model
finishes generating.

#+begin_src lisp
;; Parse complete JSON (no healing)
(cl-llama-cpp-extras/json-partial:json-partial-parse "{\"name\":\"Alice\"}")
;; => "{\"name\":\"Alice\"}", NIL, ""

;; Heal partial JSON with a healing marker
(cl-llama-cpp-extras/json-partial:json-partial-parse
  "{\"name\":\"Ali"
  :healing-marker "$HEAL$")
;; => "{\"name\":\"Ali$HEAL$\"}", T, "$HEAL$"
;; The json-dump-marker (third value) locates where healing begins in the output
#+end_src

Returns three values: the parsed JSON string, whether healing was applied (=T= or
=NIL=), and the json-dump-marker (a string that locates the healing boundary in
the output). Signals =json-partial-parse-error= when the input cannot be parsed
or healed, a subtype of =json-partial-error= (itself a subtype of
=cl-llama-cpp:llama-error=).

*** =cl-llama-cpp-extras/speculative=

Self-speculative decoding via n-gram prediction (=NGRAM_SIMPLE=). The model
drafts candidate tokens based on n-gram patterns in the prompt, then verifies
them in a single batch — no separate draft model required.

#+begin_src lisp
;; Create params and configure n-gram speculative decoding
(cl-llama-cpp-extras/speculative:with-speculative-params (params)
  (cl-llama-cpp-extras/speculative:speculative-params-add-type
    params cl-llama-cpp-extras/speculative:+speculative-type-ngram-simple+)
  (cl-llama-cpp-extras/speculative:speculative-params-set-ngram-n params 4)

  ;; Initialize the speculative context
  (cl-llama-cpp-extras/speculative:with-speculative-context (ctx params)
    ;; Begin with prompt tokens
    (cl-llama-cpp-extras/speculative:speculative-begin ctx 0 prompt-tokens)

    ;; Draft/verify loop
    (let ((drafted (cl-llama-cpp-extras/speculative:speculative-draft ctx
                     :seq-id 0
                     :n-past n-past
                     :id-last last-token
                     :prompt-tokens prompt-tokens)))
      ;; ... verify drafted tokens with target model ...
      (cl-llama-cpp-extras/speculative:speculative-accept ctx 0 n-accepted))))
#+end_src

Signals =speculative-init-error= (a subtype of =cl-llama-cpp:llama-error=) on
initialization failure.

Currently supported types: =+speculative-type-ngram-simple+= (self-speculative,
no draft model). Draft-model types (=DRAFT_SIMPLE=, =EAGLE3=, =MTP=) are defined
as constants but require cross-package batch access and are deferred.

*** =cl-llama-cpp-extras/reasoning-budget=

Limit how many tokens a reasoning model (DeepSeek-R1, QwQ, etc.) can spend
inside a =<think>...</think>= block. Wraps =common/reasoning-budget.h= — a
=llama_sampler= with a state machine
(=IDLE → COUNTING → WAITING_UTF8 → FORCING → DONE=) that counts tokens after a
start sequence and forces an end sequence once the budget runs out.

The sampler is created via a shim because the upstream C++ API takes
=std::vector<llama_token>&= parameters.

#+begin_src lisp
;; Load the extension
(asdf:load-system "cl-llama-cpp-extras/reasoning-budget")

;; Tokenize the start/end/forced sequences for your model.
;; For DeepSeek-R1 style models, these are typically:
;;   start  = "<think>"
;;   end    = "</think>"
;;   forced = "</think>"  (what gets injected when budget expires)
(let* ((start-tokens  (cl-llama-cpp:tokenize model "<think>"
                        :add-special nil :parse-special t))
       (end-tokens    (cl-llama-cpp:tokenize model "</think>"
                        :add-special nil :parse-special t))
       (forced-tokens (cl-llama-cpp:tokenize model "</think>"
                        :add-special nil :parse-special t))

       ;; Create the sampler — allow up to 1024 thinking tokens
       (rb (cl-llama-cpp-extras/reasoning-budget:make-reasoning-budget-sampler
             model start-tokens end-tokens forced-tokens 1024)))

  ;; Add it to your sampler chain (before the sampling strategy).
  ;; The chain takes ownership — freeing the chain frees this sampler too.
  (cl-llama-cpp:with-sampler-chain (chain :model model :temp 0.6 :min-p 0.1)
    (cl-llama-cpp:sampler-chain-add chain rb)
    (cl-llama-cpp:generate ctx prompt :sampler chain)))
#+end_src

The sampler works as a logit filter: in =FORCING= state it sets all logits to
=-inf= except the next forced token, guaranteeing the end sequence is emitted.
In all other states it's a passthrough.

#+begin_src lisp
;; Query the state machine at any point
(cl-llama-cpp-extras/reasoning-budget:reasoning-budget-state rb)
;; => :IDLE, :COUNTING, :WAITING-UTF8, :FORCING, or :DONE

;; Manually force an early end to thinking (only works from :COUNTING)
(cl-llama-cpp-extras/reasoning-budget:reasoning-budget-force rb)
;; => T if transition occurred, NIL otherwise
#+end_src

The sampler re-arms on a new =<think>= tag after reaching =DONE=, so models
that emit multiple thinking blocks each get a fresh budget window.

Signals =reasoning-budget-init-error= (a subtype of =cl-llama-cpp:llama-error=)
if sampler creation fails.

*** =cl-llama-cpp-extras/chat=

Structured chat template rendering and tool-call parsing via llama.cpp's
=common/chat.h=. Provides Jinja-based template rendering, GBNF grammar
generation for constrained tool calling, and output parsing into structured
messages. This is the higher-level layer above =cl-llama-cpp='s =chat.lisp=
(which wraps the simpler C function =llama_chat_apply_template=).

#+begin_src lisp
;; Create a templates handle from a loaded model
(cl-llama-cpp-extras/chat:with-chat-templates (tmpls model)

  ;; Render messages to a prompt + grammar for constrained generation
  (let* ((messages (list (list :role "system" :content "You are helpful.")
                         (list :role "user" :content "What's the weather?")))
         (tools (list (list :name "get_weather"
                            :description "Get current weather"
                            :parameters "{\"type\":\"object\",\"properties\":{\"location\":{\"type\":\"string\"}},\"required\":[\"location\"]}")))
         (result (cl-llama-cpp-extras/chat:chat-templates-apply
                   tmpls messages :tools tools)))
    ;; result is a plist: :PROMPT, :GRAMMAR, :FORMAT, :GRAMMAR-LAZY, ...
    (let ((prompt (getf result :prompt))
          (grammar (getf result :grammar)))
      ;; Use prompt + grammar for constrained generation
      (cl-llama-cpp:generate ctx prompt :grammar grammar))))
#+end_src

Parse model output back into structured messages:

#+begin_src lisp
;; Parse content-only output (no tool calls)
(cl-llama-cpp-extras/chat:chat-parse "Hello!")
;; => (:ROLE "assistant" :CONTENT "Hello!")

;; Validate a chat template string
(cl-llama-cpp-extras/chat:chat-verify-template
  "{% for message in messages %}...{% endfor %}" :use-jinja t)
;; => T or NIL
#+end_src

The templates handle needs a GC finalizer or =with-chat-templates= for cleanup.
It must not outlive the model it was created from.

Signals =chat-init-error= (template/apply failures) and =chat-parse-error=
(parse failures), both subtypes of =cl-llama-cpp:llama-error=.

** Requirements

- [[https://github.com/licjon/cl-llama-cpp][cl-llama-cpp]] with llama.cpp built (=libllama-common.so= must exist)
- A C++17 compiler (for building the shim)

** Installation

Clone into your ASDF source registry alongside =cl-llama-cpp=:

#+begin_src bash
cd ~/.roswell/local-projects   # or ~/common-lisp/
git clone https://github.com/licjon/cl-llama-cpp-extras
#+end_src

The unified C++ shim (=libllama-extras-shim.so=) is built automatically on first
load of any extension. It rebuilds whenever =libllama-common.so= or any shim
source file is updated, so upgrading llama.cpp in =cl-llama-cpp= is handled
transparently.

Load individual extensions:

#+begin_src lisp
(asdf:load-system "cl-llama-cpp-extras/json-schema")
(asdf:load-system "cl-llama-cpp-extras/json-partial")
(asdf:load-system "cl-llama-cpp-extras/speculative")
(asdf:load-system "cl-llama-cpp-extras/reasoning-budget")
(asdf:load-system "cl-llama-cpp-extras/chat")
#+end_src

** Examples

#+begin_src lisp
(asdf:load-system "cl-llama-cpp-extras/examples")
#+end_src

| File                      | Demonstrates                                                      |
|---------------------------+-------------------------------------------------------------------|
| =examples/json-schema.lisp= | Schema → GBNF conversion, constrained generation, error handling |

Run without a model (demos 1 and 3 only need the shim):

#+begin_src lisp
(cl-llama-cpp-extras/examples/json-schema:run)
#+end_src

Run with a model (all demos):

#+begin_src lisp
(setf cl-llama-cpp-extras/examples/json-schema::*model-path*
      "/path/to/model.gguf")
(cl-llama-cpp-extras/examples/json-schema:run)
#+end_src
